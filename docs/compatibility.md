# hb compatibility contract — v0.18 preview

The source of truth is `hb api --json`, generated by
`scripts/generate_manifest.py` from `#[doc = "hb:symbol=..."]` contract tests.
Golden scripts execute unchanged inside hb and Blender 4.5.9 LTS, except explicitly
marked legacy OBJ fixtures use the original operators in Blender 3.6.23. The observer
compares object names, hierarchy, selection, transforms, mesh topology, UVs,
materials/nodes, cameras, lights, images and collections. Export comparisons
also check GLB node matrices, hierarchy, primitive counts and bounds. The Blender
reference export explicitly sets `export_apply=True` to compare evaluated modifiers. Material
parameters must match at float32 precision.

## Unsupported

The implemented data API covers common assembly operations, not every Blender
RNA property. Access to unsupported namespaces and properties raises
`hb.UnsupportedError`; errors include `code`, `message`, `location`, `suggestion`
and `doc`. Runtime tracebacks contain user frames only. The modeling increment
adds Vector, basic standalone bmesh, mesh primitives, mesh joining and the
modifier subsets below. CLI/server operations and the declared bpy I/O/render
operators use the same native asset and raster pipelines.

The tested node graph has one Principled BSDF and one material output. Images may
feed Base Color, Alpha, or a tangent-space Normal Map. Principled scalar/color
inputs support metallic, roughness, emission and alpha. Other nodes/connections
fail. Connected texture nodes must have an assigned image before preview/export. Cube UVs and explicit UV loops are supported; automatic unwrapping is not.

## Static checker

`hb check` parses without executing. Lexical function bindings are separated,
so helper functions can reuse local names. A monotone analysis follows API
values through direct helper arguments/returns, assignments, branches, simple
containers and container append/extend. Dynamic API attribute names and
unsupported literal ARRAY types/settings are rejected. Inference is bounded to
64 passes and reports an unresolved error if it does not converge.

Plain Python tuple-coordinate inputs can be converted to `mathutils.Vector` in
helpers without the checker treating retained tuple-position metadata as an API
path. Tuple members carrying `bpy`, `bmesh` or `mathutils` provenance still undergo
API validation. This does not validate arbitrary Python attribute access.

This is still **not a sound verifier for arbitrary Python**. Higher-order calls,
classes, closures, complex destructuring and dynamically reconstructed objects
can evade inference; union types can cause false positives. Property-specific
parameter/state validity is also checked at runtime. Universal checker soundness is
won't do (unbounded arbitrary-Python analysis), not a claim of this release. MCP automatically runs the checker
before execution, but the calling application must still isolate untrusted scripts.

## Modeling foundation

- `mathutils.Vector`: 2D/3D/4D float32 values, component mutation/swizzles,
  arithmetic, dot/cross, length, normalization, interpolation, projection,
  reflection and dimension conversion. Object location/scale, mesh vertex
  coordinates and UV coordinates expose mutable Vector views. Four-dimensional
  normalization leaves W unchanged, matching Blender. The 100,000-operation
  differential test is Vector-only, with absolute tolerance 1e-5 or relative
  tolerance 1e-6. Matrix, Euler, Quaternion and standalone Color are implemented with the
  limits below; this is not full mathutils parity.
- `bmesh.new`: standalone editable vertices, edges and faces, creation/removal,
  lookup tables/indices, from/to mesh, normal update and invalidation on free.
  Operators include translate, scale, rotate and transform, plus delete with
  VERTS/EDGES/FACES_ONLY contexts. Transforms accept nonsingular space matrices,
  validate vertex selections before editing and return None.
  Editable loop layers support up to eight UV layers and one FLOAT_COLOR layer;
  vertex shape layers support up to 64 relative keys. `Object.shape_key_add`,
  `Mesh.shape_keys.key_blocks` and key point coordinates provide the corresponding
  mesh data. Transforms optionally include all shape layers. Animation/mixed-key
  evaluation, other storage types and topology-operator interpolation are excluded.
  Packed custom normals round-trip on flat faces with unchanged geometry; direct
  packed-normal editing has no public Blender BMesh reference API, so use
  `Mesh.normals_split_custom_set`. Unsupported domains or remapping fail explicitly.
  Layer publication validates a complete candidate before replacing mesh data. `create_cube(size=...)` and
  `create_grid(x_segments=..., y_segments=..., size=...)` append topology and
  return only the created vertices. Grid segments clamp to at least one, with
  a 100,000-vertex resource limit. Both require `calc_uvs=False`; finite 3x3/4x4 primitive matrices are supported.
  Other unlisted bmesh operators are outside the manifest contract.
- Object-mode WORLD cube, plane, circle and cylinder operators. Circle has
  NOTHING/NGON/TRIFAN fill; cylinder has NOTHING/NGON/TRIFAN caps. Reference
  topology ordering and UVs are checked at 3/4/5/8/16/32 segments. Plane's scale
  argument is accepted but ignored, as observed in Blender 4.5.
- Ordered, non-destructive ARRAY evaluation supports fixed count (1..10000),
  relative and constant local offsets, viewport/render visibility, removal and
  first-in-stack application to single-user meshes. Object copies retain their
  independent stacks and share mesh data until copied. Merge, object offsets,
  caps and other fit modes fail explicitly. Evaluation is capped at two million
  vertices/faces and 64 modifiers. `stats` continues to count source data blocks;
  bbox/spatial queries and glTF export evaluate viewport geometry; CPU previews
  evaluate render geometry. Revisions store the source meshes and modifier descriptors.


- MIRROR applies local X/Y/Z reflections in axis order, optionally merging
  corresponding seam vertices. Merge uses a strict distance threshold; vertices
  exactly at half the threshold from the plane remain separate. Axis flags,
  clipping flag (edit-mode only), threshold, visibility and stack application
  are persisted. Mirror objects, bisect, UV offsets and vertex groups are supported within
  the bounds in the MIRROR extension section below.
- TRIANGULATE supports all five quad methods and BEAUTY/CLIP n-gons, with
  `min_vertices` filtering. BEAUTY and affected n-gons require planar simple
  polygons, at most 2048 corners. UV/color corners, face flags and vertex weights
  survive triangulation. `keep_custom_normals=True` preserves stored corner
  normals; False reinterprets their quantized corner-space angles on flat planar
  faces. Smooth custom-normal faces require True. hb stores float32 vectors;
  new normal probes allow 1e-4 for Blender's angle quantization, without changing
  existing golden tolerances. N-gon face allocation order can differ; indexed
  connectivity, winding and UV corners are checked. `normals_split_custom_set`
  accepts one finite nonzero normal per corner and validates before mutation.
- SOLIDIFY supports EXTRUDE on consistently oriented, non-degenerate manifold
  surfaces, signed thickness, offset, boundary walls, rim-only mode and material
  offsets. Even/quality/clamped offsets, vertex groups and bounded NON_MANIFOLD
  radial fans are supported; see the SOLIDIFY extension section below.
  Arbitrary degenerate repair and custom-normal propagation remain excluded.
- The three topology modifiers preserve source face material/smooth flags and
  remap all stored UV and color corners. Existing ARRAY stack visibility,
  application, resource limits and revision semantics apply to them too.

- UV spheres support `segments`, `ring_count`, nonnegative `radius`, WORLD/CURSOR
  transforms and optional UVs. Counts clamp to at least three; generated spheres
  are limited to 100,000 vertices. Zero radius requires `calc_uvs=False`, because
  Blender's generated UVs contain NaNs; the untextured result is an unmerged quad grid. Sphere indices follow
  the stable layout documented in `compat/DEVIATIONS.md`; geometry, winding and
  UVs are checked independently of vertex/face order at 1e-5.
- Cone/frustum and cylinder creation support nonnegative radii/depth, three cap
  modes, optional UVs and WORLD/CURSOR transforms. Both radii zero produce two
  wire vertices; zero depth is supported. Explicit positive or zero construction
  scale is supported with UVs; negative scale requires `calc_uvs=False`.
  Plane/circle construction scale remains ignored, matching Blender. Explicit
  zero cube size uses a unit cube; explicit zero scale collapses scaled primitives.
- `bmesh.ops.create_uvsphere`, `create_cone` and `create_circle` append topology,
  preserve existing elements and return only new vertices. They require at least
  three segments (and sphere rings), finite dimensions, positive sphere/circle
  radius, nonnegative cone radii/depth and `calc_uvs=False`. Finite 3x3/4x4
  matrices transform only the newly created vertices.
  Cone `cap_ends`/`cap_tris` select open/ngon/triangle-fan construction. Sphere
  index-order deviation and construction resource limits also apply here.

- Torus creation uses Blender's `generate_uvs` keyword (not `calc_uvs`) and
  has no creation `scale` or `enter_editmode` argument. WORLD/CURSOR alignment,
  existing EDIT context, location/rotation, MAJOR_MINOR and EXT_INT modes are supported.
  Segment counts clamp to 3..256 on both axes; radii clamp to 0..10000 before
  validation. `0 <= minor_radius <= major_radius` is supported, including zero
  and horn tori. Self-intersecting spindle radii remain excluded.
  Indices, face winding and seam UVs match the reference without sphere-style
  index equivalence. Apply object scale after creation if needed.
- `bpy.ops.object.join` combines selected meshes through their world transforms
  into a selected active mesh with a nonsingular world transform. Reflected
  scales, parents, children and shared data are supported. Joining updates all
  users of the active mesh; deleting a source detaches its children. Joining a
  direct active parent bakes the active object's world transform before detaching
  it. Indirect active ancestors, modifiers and indexed custom data other than UVs
  are excluded. Valid material slot indices are required. Names and unused mesh
  data remain. Geometry is converted into the active mesh's local frame.
  Material slots and face indices are remapped, smooth flags and loose edges are
  preserved, UV layers merge by name with zero-filled missing corners. The first
  source with UVs supplies the active UV layer when the target has none.
  Joining returns `{'CANCELLED'}` if there are no source vertices to add to the active mesh. The result is limited to two million
  vertices/faces. Joining changes ownership, not connectivity; it does not weld.
- Creating a first UV layer with `do_init=True` uses Blender's triangle/quad face
  layout or circular n-gon layout. Additional layers copy the active layer;
  `do_init=False` zero-fills the new layer.

- `bmesh.ops.extrude_face_region` accepts faces or mixed BMVert/BMEdge/BMFace
  input in a standalone BMesh, including wire edges and isolated vertices.
  Selected faces must form a consistently oriented manifold region whose boundary
  loops do not meet at a shared corner. Empty input returns `{'geom': []}`.
  Duplicated vertices, edges and cap faces are returned; side walls are excluded
  from the result. The operation does not translate or scale the new geometry.
  For face-only input Blender retains and flips the input caps for both values of
  `use_keep_orig`. Remove retained intermediate caps when extending an existing
  solid, then call `normal_update` after moving vertices. Material indices and
  smooth flags are inherited. Mixed face input requires one connected region;
  explicit adjacent edges remove original caps when `use_keep_orig=False` and
  selected boundaries touch unselected faces. New walls then inherit the exterior
  face flags. Retained attached caps require flat incident faces because smooth
  non-manifold vertex welding is outside the verified export subset. Pure edges
  add walls; isolated vertices add connectors. Excluded
  edges and non-default normal/dissolve/history flags remain unsupported.
  Topology interpolation for editable custom layers is excluded.
  Construction is limited to 100,000 vertices/faces. Side walls have deterministic
  ordering; mixed vertex/edge traversal can also differ. See `compat/DEVIATIONS.md`
  and the contract tests.
  GLB export preserves separate face material-slot groups, including empty slots.

- `bmesh.ops.recalc_face_normals(bm, faces=...)` repairs winding for selected faces using their complete
  connected orientable manifold components with planar, non-degenerate faces. It
  preserves vertex/edge/face traversal order and each face's first corner, along
  with material indices, smooth flags and live handles. It refreshes all face
  normals and sequential element indices, including on unselected geometry;
  an empty selection performs that refresh too. The return value is `None`,
  matching Blender 4.5.9. Disconnected and nested shells orient independently.
  Open components use extremal-corner orientation; closed components use signed volume.
  Call `normal_update()` after coordinate edits before repair.
  Non-manifold vertices/edges, non-orientable topology,
  non-planar or degenerate faces and ambiguous near-zero signed volumes fail
  before mutation. Duplicate face handles raise `ValueError`. Custom layers
  are supported by BMesh transfer but excluded from winding repair.
  The limit is 100,000 vertices/faces.
  In component coordinates normalized by the largest bounding-box extent,
  doubled face area must exceed 1e-12, planarity error is at most 1e-6, and
  absolute six-times signed volume for closed components must exceed 1e-10. This is a winding repair; it does not detect or repair geometric self-intersections.
  The checker validates the call signature; topology eligibility is checked at
  runtime. `BMesh.normal_update` now avoids cancellation on translated geometry.

- WELD supports ALL greedy proximity groups and CONNECTED edge collapse with
  updated cluster centers. Positions and memberships are averaged; duplicate,
  collapsed and pinched faces are cleaned up while UV corners are interpolated.
  ALL uses original-index seed order and strict spatial-partition bounds; zero
  leaves vertices separate. CONNECTED includes equality, even at zero, and can
  restrict itself to loose edges. Surface edges follow closing-corner-first face
  construction; loose wires retain input order. Arbitrary imported edge-allocation
  parity is outside this subset. A named vertex group selects nonzero weights;
  inversion selects zero/missing weights. Missing group names select all vertices.
  Limits: 65,536 vertices per cluster, two million vertices/faces/proximity visits
  and four million input corners; squared float32 thresholds must be finite.
  Custom corner normals/colors during merging and unbounded “general welding”
  remain unsupported. Runtime failures preserve the revision. glTF export uses
  `show_viewport`; raster preview uses `show_render` for every modifier.

- BOOLEAN supports EXACT/FAST/MANIFOLD selection for DIFFERENCE/UNION/INTERSECT
  on closed, consistently oriented solids through vendored Manifold 3.5.2. This
  bounded contract does not reproduce Blender's separate solver internals or
  arbitrary-mesh precision behavior. OBJECT and recursive COLLECTION operands
  support evaluated stacks, cavities and polygon holes. Collections allow 64 mesh
  operands; FAST collection INTERSECT is unsupported, with an EXACT hint.
  EXACT/FAST accept reflected nonsingular relative transforms; MANIFOLD retains
  its orientation-preserving restriction because reflected reference results are
  inconsistent. INDEX material mapping and default advanced settings are supported.
  UV layers, custom corner normals and one FLOAT_COLOR CORNER color attribute are
  interpolated. Additional color domains/types/layers are outside this subset.
  Geometry is validated before commit; cycles/depth above 64 are rejected. Inputs
  allow one million vertices/faces and two million triangles; outputs allow two
  million vertices/triangles. Work limits are 10 million coplanar tree visits,
  two million hole-merge candidates per face and 20 million corner interpolation
  contributions. Canonical coplanar partitions and redundant collinear vertices
  can differ from Blender; oriented patch boundaries, holes and attributes are
  reference-tested. Existing MANIFOLD ordering deviations remain documented in
  the BOOLEAN contract tests.

- BEVEL supports closed outward-wound convex polyhedral meshes with planar convex
  faces: cylinders, cones, prisms, triangulated convex solids and other convex
  meshes. EDGES, OFFSET, segments 1..8 and NONE/ANGLE are supported. Face insets,
  rational edge fillets and corner patches form a checked closed surface;
  clamping conservatively avoids local face collapse. Material slots and
  projected per-face UVs are retained. Concave/open/non-manifold geometry, loose
  elements, non-planar faces, custom normals/colors, creases, shape keys and
  deform weights are rejected. General topology/UVs are not Blender-identical.

  The reference-exact legacy path remains for canonical eight-vertex, six-face cuboids from cube creation,
  including dimensioned and rigidly transformed vertex coordinates. It supports
  EDGES or VERTICES with OFFSET, 1..8 segments, profile 0.5, ANGLE/NONE limits
  and default advanced settings. `use_clamp_overlap=True` clamps width to half the
  shortest local edge with a positive gap no larger than 1e-6 to retain
  triangulable limit faces. The evaluated float32 triangles are checked before
  modifier commit at review's relative area threshold. If the gap still produces
  numerically degenerate faces (for example a 2×1×0.002 m panel, width 0.08 m,
  segments 2), HB rejects with requested/evaluated width and the half-thickness
  limit. Reduce width/segments or increase thickness; no universal design clamp
  is applied. False requires a nonoverlapping width.
  Zero width and an angle threshold above 90° leave evaluated geometry unchanged.
  Applying a zero-width bevel raises Blender's disabled-modifier error.
  UV interpolation supports affine quads with the cube primitive's corner seam
  layout, or six separate face islands. Multiple layers must share that layout.
  UVs use measured source-face/projection labels and face-area weighted corner
  averaging, including Blender's narrow-width transition. Odd segment counts on
  textured meshes require axes aligned with local X/Y/Z; object rotation may
  remain unapplied. Even segment counts support baked orthogonal rotation.
  Textured VERTICES supports segment 1 and even counts; odd 3/5/7 are supported
  without UVs. This restriction retains the unchanged 1e-5 UV tolerance at tiny
  corner faces. Non-affine or other seam layouts, near-but-unequal joined UVs,
  custom corner normals/colors and nonuniform material/smooth flags fail
  explicitly on this legacy cuboid path. Other profiles remain unsupported.
- `bpy.ops.object.transform_apply` bakes any combination of location, rotation
  and scale into selected TRS mesh objects with nonzero scales, including
  reflections and parent/child compensation. `isolate_users=True` copies data
  for partially selected shared users; selecting every user applies data once
  and compensates other users' selected transform channels. Shared selected
  users must be unparented without children. Shape keys, raw matrix overrides,
  reflected packed normals and non-mesh objects are excluded. Mesh UVs/materials
  are retained.
  Applying dimensions before BEVEL gives its width consistent mesh-space units.
- Preflight accepts cube primitives with UVs. Mesh topology, UV eligibility and
  general Python control flow still require runtime validation; this is not a
  sound geometry verifier. Invalid evaluated bevels fail before revision commit.

The manifest defines the supported modifier/BMesh/operator bounds. Full Blender
parity and universal checker soundness are outside this contract.

## I/O

The `bpy.ops.import_scene.gltf` operator imports into the active collection with
Blender selection, hierarchy and quaternion poses. Imported scalar Principled
inputs remain editable and update exported material factors. Native texture
bindings are retained; arbitrary generated shader graphs are not reconstructed.
`export_scene.gltf` supports GLB and separate glTF/bin, selection, applied
modifiers and optional camera/light export. Its defaults match Blender: modifiers
unapplied, cameras/lights omitted.

Legacy `import_scene.obj` uses its declared forward/up axes (default -Z/Y),
selects imported objects and retains the previous active object. Its scalar MTL
conversion follows Blender 3.6; the existing CLI importer retains its Z-up
interpretation. `export_scene.obj` supports mesh selection, modifiers, normal/UV
references, triangulation, axes and positive global scale, scalar MTL and
base/alpha/normal image output. Packed metallic/roughness maps report a warning
and retain scalar factors. Each output file is replaced atomically; multiple
files and the scene revision are not a single atomic transaction.

- GLB and glTF 2.0, external/data-URI buffers, byte strides, sparse and normalized
  accessors, triangles/strips/fans, mesh instances, parent hierarchies, multiple
  material primitives, embedded/external PNG and JPEG, normals, up to eight UV layers and colors.
- Base color, metallic/roughness and normal textures; emissive factors and
  KHR_materials_emissive_strength. KHR_lights_punctual and mesh quantization.
- Repeat wrapping and bilinear preview sampling. Clamp/mirror wrapping, textures referencing nonzero UV
  channels, texture transforms, emissive/occlusion textures, Draco, meshopt, KTX,
  animation, skins and unsupported extensions are rejected explicitly.
- OBJ/MTL: groups/objects, polygon faces, negative indices, UVs/normals, material
  groups, diffuse textures, opacity, metallic/roughness and Ns conversion. OBJ
  coordinates are explicitly interpreted as Z-up meters. Legacy ambient/specular
  MTL values are not represented by this PBR preview model; import reports that.
- CLI `hb export file.obj` and `hb run script.py --out file.obj` export evaluated
  linked meshes in Z-up meters, with reflected winding, per-corner UVs/normals,
  scalar MTL and PNG image companions. Original object/mesh names survive modifier
  evaluation; sanitized material names include stable IDs to prevent collisions.
  OBJ normals use Blender's four-decimal output precision. Each file is replaced
  atomically; companion files and the scene revision are not one transaction.
  The `hb.export.obj` manifest entry documents this CLI format, not a Python API.
- USDZ export packages a USDA default layer and PNG assets in an uncompressed,
  unencrypted ZIP with each entry aligned to 64 bytes. Evaluated meshes retain
  hierarchy, polygon/corner attributes, face material groups and scalar/textured
  UsdPreviewSurface materials. Cameras and POINT/SPOT/SUN/AREA lights use USD
  units. Generated floating images use 16-bit PNG; byte images use 8-bit PNG;
  source PNG assets retain their bytes. Color textures use USD's `auto` rule,
  with normal/metallic-roughness/data textures marked `raw`. World environments
  are omitted with a warning. Names use valid USD identifiers and retain the
  source name in metadata. The archive is replaced atomically.
  Orthographic aperture units follow the USD standard; Blender 4.5 imports their
  scale 10x too large. Export warns to divide imported `ortho_scale` by 10 or
  use a perspective camera. This is a measured consumer limitation.
- GLB or self-contained glTF includes all mesh UV layers. Normal
  export rounds to four decimal places before normalization, matching Blender. Standard glTF cannot express Blender lens
  shift or area lights: exports warn and preserve them in `extras.hb_camera` and
  `extras.hb_area_light`; hb restores these extras on import. Generic viewers do
  not implement these extras. Separate alpha/base-color images must be combined
  before glTF export. The CLI format expansion for STL and PLY
  is tracked separately in the compatibility backlog.

Imported PBR factors are represented in native material metadata. Changing a
material's diffuse_color/metallic/roughness updates these factors. Enabling a new
bpy node tree replaces the imported shading with that tree, as an explicit edit.

## Rendering and queries

`bpy.ops.render.render` renders the current scene camera with the existing CPU
raster preview. It respects resolution percentage and pixel aspect, up to 2048
pixels per axis. `write_still=True` writes PNG to `scene.render.filepath`;
`False` computes without writing. Animation and viewport overrides are excluded.
The operation does not retain Blender's volatile Render Result image datablock,
and its pixels are not an EEVEE/Cycles equivalence claim. The Blender reference
checks file behavior and resolution; scene and GLB comparisons remain unchanged.

Default draft previews use GGX direct lighting, directional/spot/cube shadow maps, four point
samples for square area lights, simple screen-space AO, tone mapping, and
back-to-front triangle alpha blending. They are deterministic visual feedback,
not EEVEE or Cycles parity. Transparent intersections, small shadow details and
indirect/reflected lighting have the usual raster-preview limitations. No lights
means an hb studio rig. A missing active camera means a fitted camera panel;
requesting a nonexistent named camera is an error.

`bbox` uses world-space vertices. `distance` uses triangle surfaces with BVH
pruning, not bounding-box distance. `overlaps` reports surface contact/intersection
or closed-mesh containment. `inside` supports closed convex targets and rejects
concave/open targets. `floating` means no surface contact with another linked mesh;
it does not assume an implicit ground plane. `visible` clips triangles against
all six camera-frustum planes; it explicitly does not test occlusion. Queries
include their method/tolerance where relevant. Stats count unique mesh data blocks; render metadata counts evaluated instances.
Loading large compressed scenes
can dominate CLI query time; the <20 ms query aspiration is not met for all assets.

## Units

Coordinates use right-handed Z-up meters; object rotations support six Euler orders
and quaternions, with XYZ as the default.
Cameras look down local −Z with local +Y up. glTF basis conversion applies to both
geometry and hierarchy; camera/light local axes are handled separately. Warnings
cover suspicious angular/scene scales, zero-area triangles, materials without mesh-slot references
and objects outside the active camera's square preview frustum.

## Errors and revisions

Script failures never commit a new scene head. Scene JSON/float parsing is exact
round-trip so snapshot hashes remain stable. Snapshots use `HBR1` + zlib; the
`.hb` file contains a `hb-head-v1` pointer. Save the sidecar with the head. Unknown
or corrupted revisions fail validation. A crashed writer may leave a `.lock`;
check its PID before deleting that stale lock. Export/render output is atomic,
but a run's optional export and head update are not a cross-file atomic transaction.

- SUBSURF evaluates CATMULL_CLARK or SIMPLE at viewport/render levels 0..6.
  Catmull–Clark supports quality-3 limit patches and finite refinement
  (`use_limit_surface=False`), ALL/PRESERVE_CORNERS boundaries and
  PRESERVE_BOUNDARIES UV smoothing. Material indices, smooth flags, up to eight
  UV layers and their seams are retained. Edge and vertex creases are exposed as
  `crease_edge` FLOAT EDGE and `crease_vert` FLOAT POINT attributes, with finite
  values in 0..1. `use_creases=False` disables their geometric influence while
  retaining interpolated attributes. One corner color layer is interpolated on
  the original faces. Custom normals default to recomputed geometric normals;
  `use_custom_normals=True` preserves packed normals on flat inputs at levels
  1..2. Higher-level and smooth-input preservation fail explicitly, retaining the
  verified 1e-4 normal tolerance. Surfaces must be consistently oriented and
  manifold; open boundaries are allowed. Disconnected wires use cubic B-spline
  interpolation (linear for SIMPLE), with sharp branch/end junctions; isolated
  vertices are retained. Wire-to-surface junctions and vertex-group interpolation
  remain outside this bounded subset and fail explicitly. Refined geometry is
  limited to two million vertices/faces, including the quality-3 safety estimate.
  Vertex/face ordering is stable within hb and compared by vertex bijection and
  oriented connectivity.

- DISPLACE uses persistent grayscale CLOUDS textures with the CELL_NOISE basis,
  soft/hard octaves, brightness/contrast, local NORMAL/X/Y/Z directions and LOCAL
  texture coordinates. The BLENDER_ORIGINAL default is readable but unsupported
  for evaluation. Missing textures produce uniform displacement. UVs, materials
  and topology are preserved. Named vertex groups multiply displacement by their
  weight (optionally inverted); missing groups leave it unmasked. Custom corner
  normals are remapped for flat input faces; smooth custom-normal inputs fail
  explicitly. Group memberships are preserved. Lattice coordinates are bounded to signed 32-bit cells and work
  to ten million vertex-octaves.

## Weighted normals

WEIGHTED_NORMAL supports all three area/angle modes, integer contrast 1–100,
threshold 0–10, keep_sharp and viewport/render visibility. Named vertex groups
filter membership (including zero-weight members), with optional inversion;
missing groups do not filter. Face influence uses the strongest adjacent values
from `__mod_weightednormals_faceweight` INT FACE, with strengths 0/1/2. Existing
custom normals are accepted when values agree within each smooth fan. Finite
vanishing sums fall back to geometric normals or retained custom normals as
appropriate; nonfinite arithmetic fails. UVs, materials, colors, groups, face
strengths and topology remain unchanged. Input custom-normal discontinuity
reconstruction is excluded. See [documented deviations](../compat/DEVIATIONS.md)
for the composed-bevel tolerance.


## Rotation algebra, Color and scene lighting

Matrix supports square 2x2/3x3/4x4 values, row mutation, matrix/vector products,
identity/translation/rotation/scaling/diagonal construction, inverse, transpose,
determinant, resizing and rotation conversions. Euler supports six orders;
object Euler views follow `Object.rotation_mode` (XYZ while quaternion mode is
active). Changing Euler order keeps the stored angles; crossing the Euler/quaternion
boundary converts orientation and normalizes the quaternion on exit. Set the object
mode directly; writing the Euler view order is outside this contract.
Quaternion supports components/axis-angle,
normalization, conjugation, inverse, products and matrix/Euler conversion.
Vector tracking is available. Not all Blender mathutils methods exist.

Standalone Color supports float32 RGB/HSV, arithmetic, freezing and eight
factory-space conversions. RGB RNA properties remain restricted numeric views;
custom OCIO working spaces are unsupported. Positive scene-linear components
for sRGB encoding are limited to 1e10. See [documented deviations](../compat/DEVIATIONS.md).

World supports color and a Background with color/strength/environment inputs.
The fixed preview uses constant illumination, including the environment mean.
Camera/light/empty creation, dimensions, area lights and shadow toggles remain
available. Affine `Object.matrix_world`, six Euler orders, bounded POLY curves
and explicit-font ASCII Text are supported. Constraints are unsupported. Consult the manifest for tested symbols.

Generated floating images default to `Linear Rec.709`; byte images default to
`sRGB`; data images use `Non-Color`. Whole RGBA pixel writes preserve float values
in the scene. Preview/export images use 8-bit channels. Linear generated color
textures are encoded as sRGB for glTF, while data textures retain linear channels.
A linear image used for both color and data requires separate datablocks before
export. This is not an HDR texture pipeline. The colorspace setter currently
supports sRGB and Non-Color, not arbitrary color-management configurations.

CLI `hb import file.stl` reads standard ASCII and little-endian binary STL,
including binary headers beginning with `solid`. Coordinates are finite float32,
interpreted as Z-up meters, with exact-coordinate vertex welding and Blender's
duplicate/repeated-vertex triangle cleanup. Collinear triangles and unused vertices
remain; imported corner normals are computed from geometry, with +Z for a
zero-area face. Imported meshes are flat, without UVs/materials. Limits are
100,000 input triangles, 100,000 unique vertices and 32 MiB per file. The complete
asset is validated before any scene/history changes. Binary facet attribute/color
bytes are ignored with a warning. Facet-normal override, multiple concatenated
ASCII solids and unnamed nonstandard STL extensions are outside this contract.

CLI `hb import file.ply` reads PLY 1.0 ASCII, binary little-endian and binary
big-endian encodings. Standard signed/unsigned 8/16/32-bit integers and
float32/float64 scalar/list properties are parsed in their declared order. The
mesh contract is XYZ vertices, `vertex_indices`/`vertex_index` polygon lists,
`vertex1`/`vertex2` edges, vertex `s`/`t` UVs, nonzero vertex normals and
uchar/float RGB(A). RGB is decoded from sRGB, negative RGB is zeroed and HDR values are retained; alpha is linear and unbounded. Colors are stored
per face corner; colors on loose vertices warn that they are not retained.
Unknown attributes, including face `texcoord` lists, are skipped with a warning.
Partial XYZ/normal/UV/RGB groups and zero custom normals fail explicitly; omit
normal properties to use geometry normals. Bounds are 32 MiB, 100,000 rows per
element, 32 element types, 64 properties per element, 2048 corners per face,
300,000 edges and four million scalar values. Duplicate/repeated-vertex faces
are removed while valid boundary edges remain. Invalid indices, truncation,
nonfinite values and type overflows leave the revision and sidecar untouched.
Blender's custom-normal encoding can differ from stored float normals by up to
5e-5 in the measured fixture; PLY color comparisons use 1e-6 absolute tolerance.

ARRAY now supports owner-relative object offsets, adjacent-copy merging, optional
first/last merging and evaluated start/end mesh caps. The affine offset can rotate,
scale or reflect copies and composes with relative/constant translation. Caps are
placed one step before/after the array; their object transforms are ignored and
material indices use the source object's slots. Merging retains target coordinates,
removes collapsed/duplicate faces and preserves surviving corner UVs, colors and
normals. `merge_threshold` is inclusive, including exact duplicates at zero, within
0..1. First/last merging can retain last-copy coordinates and reorder surviving
vertices. Limits remain two million evaluated vertices/faces, with two million
proximity checks. A nonadjacent repeated corner created by a merge fails explicitly;
reduce the threshold. Cap dependencies cannot be cyclic. Other fit modes are
outside the explicitly requested subset.

MIRROR supports an object-defined affine plane, per-axis bisect/flip masks,
near-plane snapping, copied UV reflection/offsets and vertex-group swapping.
Bisection supports one cut segment per face; cut corners and deform weights are
interpolated. Merged seam weights average the source and mirrored memberships.
Matching side names include separated L/R suffixes/prefixes and Left/Right word
prefixes/suffixes, with numeric suffixes retained; standalone side words are not
flipped. `use_mirror_vertex_groups=False` preserves group indices. UV offsets and
mirror offsets are each in -1..1; bisect threshold is in 0..1. Other limits retain
the two-million evaluated vertex/face cap.

Mesh objects expose named vertex groups with `new/get/remove/clear`, name/index,
`add` in REPLACE/ADD/SUBTRACT modes, membership removal and weight lookup. Mesh
vertex memberships are read-only views. Limits are 1024 groups and one million
memberships per mesh. Values clamp to 0..1; invalid indices/nonfinite assignments
fail before mutation. ARRAY propagates source weights and keeps merge-target
weights. Weighted ARRAY caps, BMesh deform layers and joining weighted meshes
are outside this contract; unsupported topology modifiers reject weighted input
explicitly. Apply those operations before assigning groups. Acquire fresh group
handles after applying a Blender modifier, since Blender can replace its group
records during that operation.

SOLIDIFY supports EXTRUDE even offsets, edge-angle quality normals (with ordinary
normal fallback at flat interior vertices), edge-length clamping and thickness
vertex groups. `thickness_vertex_group` blends a 0..1 minimum with the weight;
`invert_vertex_group` reverses the influence. Existing shell/rim output groups
receive weight one on generated inner vertices and boundary vertices respectively.
Missing group names leave full thickness and do not create new groups.

NON_MANIFOLD uses radial face fans and offset-plane constraints, including
three-or-more-face edge junctions. Its default constraint solver ignores the
EXTRUDE even/quality switches, as Blender does. Rim-only output removes unused
interior vertices. Zero plane offsets retain Blender's 1e-5 minimum shell offset,
scaled by vertex influence; zero total thickness also retains Blender's reversed
winding. UV/color corners and source deform weights follow generated faces/vertices.
Vertex allocation and cyclic face starts may differ; the oracle checks a vertex
bijection, oriented indexed connectivity, corner UVs and weights.

The extension contract requires nondegenerate planar faces and no loose geometry;
EXTRUDE remains consistently oriented manifold input. NON_MANIFOLD supports at most
64 faces per edge, one million input corners and two million output vertices/faces.
Conflicting offset planes, ambiguous junction boundaries or offsets over 1e6 fail
explicitly before publication. Custom split normals require removal before shell
generation. Unnamed boundary/thickness-solver modes, angle-clamp variants and
unbounded degenerate-input repair are outside this contract.


`Object.matrix_world` reads a 4x4 snapshot. Assign the whole matrix to update
object transforms through the effective parent inverse and Blender's TRS
decomposition, including reflections, zero target axes and shear. Input and
resulting basis components must be finite and within 1e6. Singular effective
parents and projective matrices fail before changing the object. Editing a
returned snapshot does not update the object until assignment. See
the world-matrix contract tests.


Primitive operators support transient single-mesh EDIT insertion and a construction
cursor (`scene.cursor.location` and XYZ `rotation_euler`). Cursor state starts at
zero on each script run. WORLD uses the cursor's location when location is omitted;
CURSOR also uses its rotation when rotation is omitted. Explicit transforms win.
Use `object.mode_set(mode='EDIT')` or `enter_editmode=True` on operators exposing
that keyword, then return to OBJECT before object operations or script completion.
Edit insertion requires an invertible object transform and at most 100,000 combined
vertices/faces, with ordinary geometry, materials and UV layers. Multi-object or
viewport editing, arbitrary edit-mode RNA/BMesh lifecycle and other custom-layer
interpolation are excluded. See the primitive contract tests.

### Legacy POLY and Bezier curves

`bpy.data.curves.new(name, 'CURVE')` supplies independently named Curve data. Set
`dimensions='3D'` and populate `splines.new('POLY').points` (four-component
coordinates). Open paths support 3D minimum-twist round bevel; cyclic beveled
paths must be XY-planar. Resolution 0–8 creates 4+2×resolution profile vertices;
zero bevel preserves wire edges. Point radius and tilt, spline smooth shading and
material slots are supported. Limits: 64 splines, 4096 points per spline, 100000
evaluated vertices/faces, finite coordinates within ±10000, depth/radius 0–100
and tilt within ±100 radians. Adjacent points require separation at least 1e-6;
reversing cusps are rejected.

Control data remains editable across runs and shared between objects. Surface
evaluation occurs on view-layer update, dimensions, supported in-script exports
or render, and successful script completion. The internal mesh surface cache is
excluded from `bpy.data.meshes`; objects retain `CURVE` identity. GLB, OBJ, USDZ,
geometry queries and preview consume the evaluated surface. BEZIER splines use
`bezier_points` with 3D `co`, `handle_left`, `handle_right`, handle types
FREE/VECTOR/AUTO/ALIGNED, radius and tilt. `resolution_u` (1..1024) samples
curved cubic spans; VECTOR spans remain linear. Ordinary 3D AUTO uses Blender's
chord-bisector and handle-length convention, with corner and unequal-spacing
reference probes. Moving a handle aligns its opposite ALIGNED handle unless
either is FREE. Generated tube topology/UVs are not promised to match Blender. `use_fill_caps=True` closes open tubes with flat caps and
requires positive endpoint radii. Spatial cyclic tubes use parallel transport with arc-length-distributed closure twist; exact Blender tessellation is not promised.
NURBS, 2D fill, custom profiles, taper, animation, modifiers on curves and edit-mode curve
lifecycle are outside this bounded contract. BMesh operates on Mesh data only.

### Static TrueType Text

`bpy.data.curves.new(name, 'FONT')` and `bpy.ops.object.text_add` support flat or extruded
filled printable ASCII text and newlines. Load a static TrueType `.ttf` using
`bpy.data.fonts.load(path)` and assign it to `text.font` before evaluation. Loaded
font outlines are stored once in the scene; saved scenes do not need the original
file. **The built-in Bfont is not bundled or substituted.** Nonempty default-font
text is rejected until an explicit supported font is assigned.

The contract includes 256 characters, size 0.0001–100, outline resolution 1–32,
line spacing 0–10, LEFT/CENTER/RIGHT horizontal alignment, TOP_BASELINE vertical
alignment and material slots using slot zero. Font files are at most 4 MiB, use
static `glyf` outlines and a Unicode format-4 cmap. CFF/variable/composite glyphs,
Unicode shaping, custom word/character spacing, bevel, offset and
other layout/edit modes are excluded. Glyph tessellation may choose different
internal diagonals; vertex positions, directed boundary edges, positive winding,
filled area, triangle counts and generated UVs are verified against Blender.
Text GLB checks allow vertex splits caused solely by normals on exactly zero-area
triangles, while checking every nondegenerate exported normal.
The same evaluated geometry serves GLB/OBJ/USDZ, preview and queries.

### Meshopt glTF buffers

Both `hb import` and `bpy.ops.import_scene.gltf` decode `EXT_meshopt_compression`.
The contract includes ATTRIBUTES, TRIANGLES and INDICES modes; NONE, OCTAHEDRAL,
QUATERNION and EXPONENTIAL filters; and the standard 0xa0/0xe1/0xd1 streams.
Parent view length/stride and buffer extents must match the extension. Tagged
fallback buffers are skipped; untagged URI-less placeholders require the
extension in `extensionsRequired`. Fallback buffers cannot supply compressed
bytes or uncompressed views. Compressed/decoded views are limited to 32 MiB each,
with at most 64 MiB decoded in total. Invalid streams fail before scene commit.

The existing static mesh/material import subset still applies after decoding.
Meshopt encoding/repacking, the experimental COLOR filter, animations, skins,
Draco and unnamed extensions are not added. The pinned MIT decoder and attribution
are in `third_party/meshoptimizer`.

### Materials, World and texture asset limits

Principled BSDF inputs persist; transmission and IOR use standard glTF extensions.
Other changed scattering inputs are preserved in `extras.hb_principled` with an
export warning. They do not add raster scattering algorithms. Image Texture and
one planar Mapping/TexCoord chain are supported. Texture transforms, clamp/mirror
wrapping, render UV channels 0..7 and emissive images survive glTF import/export;
the fixed preview, OBJ and USDZ reject advanced bindings with a glTF suggestion.
World permits Background and one equirectangular environment image. Draft preview
illumination uses its solid-angle mean. Optional CLI final quality uses low-frequency
directional diffuse environment lighting; no specular environment reflection or
environment occlusion. See [agent quality](AGENT-QUALITY.md).
The legacy Normal Map chain remains over scope, candidate for removal.

Mesh and curve/text surfaces share an internal evaluated mesh cache; `query stats`
counts these cached surfaces as meshes, while public `bpy.data.meshes` and
`bpy.data.curves` are separate. No generic Blender RNA/database parity is implied.


`TextCurve.extrude` accepts 0..100 and places caps at Z=±extrude, independent
of font size. It preserves outline holes and builds consistently wound side walls
from the actual cap boundaries. Zero retains the previous flat geometry/UVs.
All surfaces use material slot zero; cap UVs retain the flat mapping and each
side wall has local distance/height UVs. The same 100000-vertex/face limit applies
to the complete solid. Separate glyphs stay separate even when they touch or
overlap; text extrusion does not perform a Boolean union.
